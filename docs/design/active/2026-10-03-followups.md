# 남은 개선 과제

2026-10-03 문서 구조 개편과 배포 요청 API 점검 중에 나왔지만 미뤄 둔 일이다. 착수할 때 이 목록을 설계 문서로 옮겨 구체화한다.

## 배포 요청 API 보안 보강

운영자 GitHub 토큰이 잘못 쓰이면(예: 프롬프트 인젝션을 당한 에이전트) 승인 없이 워크로드가 배포된다. 같은 토큰으로 저장소에 직접 push할 수도 있으므로 API가 새 경로를 연 것은 아니지만, 다음 보강으로 피해 범위를 줄일 수 있다.

- Ingress 호스트 중복 거부: 다른 앱이 이미 쓰는 호스트를 CLI에서 거부한다. 지금은 `secrets.homelab.robinjoon.xyz` 같은 호스트를 다른 앱이 선언하면 Traefik이 어느 쪽으로 보낼지 보장되지 않는다.
- 이미지 출처 제한: 계약에서 `registry.homelab.robinjoon.xyz/apps/` 같은 허용 저장소만 받는다. 지금은 아무 이미지 주소나 쓸 수 있다.
- 새 앱 생성 승인: `apply-workload.yml`의 `create`에 GitHub Environment 승인을 건다.
- 워크로드 egress 제한: NetworkPolicy로 바깥 통신을 제한한다. 앱마다 필요한 통신이 달라 운영 부담이 크다.

새 워크로드 네임스페이스에는 `registry-credentials`(레지스트리 admin)와 `shared-db-app`(공유 DB 계정)이 복제되고, 워크로드가 이를 환경변수나 볼륨으로 읽을 수 있다. 앱 간 격리 최소화 원칙에 따른 절충이므로 보강할 때 함께 다시 판단한다.

## CLI와 서버의 규칙 공유

배포 요청 API 서버는 CLI 코드를 import하지 않고 일부 규칙을 따로 구현한다. 앱 이름 규칙(DNS-1123, 예약 네임스페이스 목록은 서버에 없음), `workloads/<name>/values.json` 경로, 스키마에서 `platform` 속성 제거, 목록 판정 기준이다. 표준 라이브러리만 쓰는 작은 공통 모듈로 빼서 CLI와 서버가 함께 쓰고, 서버 이미지에 포함한다. 쓰기 판단은 지금처럼 CLI가 다시 하므로 어긋나도 잘못된 쓰기가 커밋되지는 않는다.
